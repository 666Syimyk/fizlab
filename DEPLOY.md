# Развёртывание и выпуск

Сервер `server/worker.mjs` использует D1-совместимую базу через привязку `DB` и статические файлы через `ASSETS`. Локально эти интерфейсы предоставляет `scripts/serve-site.mjs`; база лежит в `data.local/fizlab.sqlite`. Supabase и Netlify для новой регистрации не используются.

Node.js для локального сервера — 24+. Параметры процесса: `PORT` (4174 по умолчанию; 0 выбирает свободный порт), `FIZLAB_DB_PATH` (путь SQLite; по умолчанию `data.local/fizlab.sqlite`). Они читаются из окружения процесса, а не автоматически из `.env`. Для тестов используйте отдельную базу.

HTTPS за прокси определяется по `X-Forwarded-Proto`, чтобы Origin браузера совпадал с адресом API. IP-адрес клиента по умолчанию берётся из TCP-соединения: присланные клиентом `CF-Connecting-IP` / `X-Forwarded-For` не должны обходить лимит попыток. `FIZLAB_TRUST_PROXY=1` допустим только за доверенным прокси, который заменяет эти заголовки; для Cloudflare Tunnel это включают в окружении до запуска Node-сервера. Без флага пользователи туннеля делят лимит IP локального прокси. После изменения окружения процесс необходимо перезапустить.

`netlify.toml` указывает на `dist/client` для статического клиента. Netlify не исполняет данный D1 Worker: рабочую авторизацию предоставляет размещение клиента вместе с API через Workers. `supabase/migrations/001_init.sql` и команды `db:*` относятся к прежней модели ролей и не являются миграциями текущей SQLite/D1-базы.

Сборка Worker удаляет из `dist/client` несовместимый Netlify-файл `_redirects`: переходы SPA обрабатывает Worker, а Netlify использует правило из `netlify.toml`. Не заменяйте fallback на `/index.html`: Cloudflare Assets перенаправляет его на `/`, что ломает прямые ссылки на темы и аккаунт.

Для постоянного размещения предусмотрены Cloudflare Workers + D1 в вашем аккаунте; перед выпуском проверьте тариф и лимиты под ожидаемую нагрузку. Создайте базу командой `npx wrangler d1 create fizlab-course`. Скопируйте `wrangler.example.jsonc` в `wrangler.jsonc` и подставьте выданный `database_id`, затем выполните `npm run build` и `npx wrangler deploy`. Укажите постоянный HTTPS URL Worker как `VITE_API_URL=https://…/api` при `npm run build:android`. Не переносите ключи или пароли в клиентский код. Файл `.openai/hosting.json` описывает ранее созданный проект Sites, но не является подтверждением публикации.

Веб-страница `/account/delete` позволяет войти и удалить аккаунт вместе с прогрессом и событиями; `/privacy` содержит описание обработки данных. Для карточки Play нужен постоянный общедоступный HTTPS URL этих страниц и контакт разработчика. Google Play требует путь удаления в приложении и ссылку для запроса удаления вне приложения: [официальные требования](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en).

Локальная проверка: `npm run build`, `npm test`, `npm run test:e2e`. Для Android установите Android Studio, SDK 36 и JDK 21, соберите подписанный AAB, создайте бесплатную карточку с подписками в Play Console и заполните Data safety. Конкретный package ID и ключ подписи до первой публикации следует проверить: `app.fizlab.course` пока рабочее значение. Подробная инструкция: [docs/android-release.md](docs/android-release.md).

Ограничение устройства реализовано отзывом прежнего access/refresh токена при новом входе. Случайный локальный идентификатор можно скопировать с модифицированного устройства; это не доказательство физического устройства. Подписка проверяется сервером через RevenueCat; при недоступности провайдера платные темы закрываются до успешной проверки. В APK и статической сборке остаются материалы курса: защита от извлечения файлов/модификации приложения потребует отдельной серверной доставки содержимого и проверки Play Integrity.

## Подписки и почта

Задайте `REVENUECAT_SECRET_API_KEY` через `npx wrangler secret put REVENUECAT_SECRET_API_KEY`. Используйте секретный ключ REST API v1, оставьте `REVENUECAT_ENTITLEMENT_ID=fizlab_pro`. Настройте продукт, base plans, entitlement, текущий offering и RTDN по Android-инструкции. Публичный SDK key `goog_…` передайте как `VITE_REVENUECAT_GOOGLE_API_KEY` только при сборке клиента. `REVENUECAT_ALLOW_SANDBOX=1` допустим исключительно в отдельной тестовой среде.

Подтвердите собственный домен отправителя в Resend, добавьте серверный секрет `RESEND_API_KEY` и задайте `AUTH_EMAIL_ENABLED=1`, `AUTH_EMAIL_FROM` с настоящим адресом подтверждённого домена. Необязательный `AUTH_EMAIL_CODE_SECRET` — отдельный случайный серверный секрет для HMAC кодов; без него используется ключ Resend. Смена этого секрета делает ранее отправленные коды недействительными. Перед продажами проверьте реальную доставку на нескольких почтовых сервисах. При отсутствии настроек UI сообщает недоступность писем; резервный код продолжает работать.

Миграции SQLite/D1 добавляются автоматически при первом API-запросе: nullable `email_verified_at`, `auth_email_codes`, `auth_password_resets`, `auth_email_requests`, `billing_deletion_queue`. Ранее зарегистрированные адреса не считаются подтверждёнными: пользователи подтверждают их в кабинете. Сначала сделайте резервную копию постоянной базы. Пароли и существующий прогресс сохраняются.

Восстановление `/recover`: `request-email-reset` принимает email и возвращает одинаковое сообщение для существующих и неизвестных аккаунтов. `verify-email-reset` проверяет одноразовый код и возвращает разрешение на смену пароля на 10 минут. `reset-password` принимает только это разрешение, новый пароль и его подтверждение; прямой сброс по email/коду без проверки не работает. После смены пароля API не создаёт сессию: пользователь переходит ко входу. Интервал повторной отправки — 120 секунд, он проверяется сервером и показывается таймером в приложении. Успешная повторная отправка отменяет старый код и разрешение; ошибка почтового провайдера сохраняет прежние.

Локальный сервер автоматически читает разрешённые почтовые и платёжные настройки из приватного `.env.server.local`. Переменные процесса имеют приоритет, включая пустое значение, которым можно явно отключить настройку. В файл поместите `AUTH_EMAIL_ENABLED=1`, `AUTH_EMAIL_FROM` и `RESEND_API_KEY`. Файлы `.env.*.local` исключены из Git и не копируются в клиентскую сборку. Наличие ключей в Vite `.env.local` само по себе не настраивает сервер Node. После изменения настроек перезапустите сервер обычной командой `npm run start:site` и проверьте `/api/auth/v1/settings`. Другой приватный файл можно указать через `FIZLAB_SERVER_ENV_FILE`; пустая строка отключает чтение файла для изолированных тестов.

Для реальной отправки войдите в [Resend](https://resend.com/login), [добавьте собственный домен](https://resend.com/docs/add-a-domain) и внесите выданные SPF/DKIM записи у DNS-провайдера. После статуса Verified [создайте API-ключ](https://resend.com/docs/create-an-api-key) с разрешением Sending access, ограниченным этим доменом. Ключ сохраните только в приватном серверном файле или хранилище секретов хостинга. `AUTH_EMAIL_FROM` должен использовать этот подтверждённый домен. Тестовый адрес `onboarding@resend.dev` [может отправлять только владельцу аккаунта Resend](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain) и не подходит для восстановления аккаунтов всех пользователей.

Перед сборкой публичных страниц задайте `VITE_SUPPORT_EMAIL` и `VITE_DEVELOPER_NAME` с настоящими контактами владельца. Уточните текст `/privacy` под фактический хостинг и процессы поддержки. Финальная карточка Play и Data safety должны соответствовать реально подключённым сервисам. `npm run check:release` проверяет наличие публичных настроек, HTTPS API и флаги доступности сервисов `/api/health`; это проверка конфигурации, а не успешной транзакции или доставки письма.

Удаление аккаунта транзакционно сохраняет непрозрачный UUID в `billing_deletion_queue`, даже если секрет RevenueCat временно отсутствует. После удаления выполняется попытка удаления профиля RevenueCat; при сбое запись остаётся для повтора. Cron `0 * * * *` в `wrangler.example.jsonc` выполняет повтор каждый час, до 25 записей за запуск. Локальный Node-сервер повторяет попытки ежечасно, пока запущен. Контролируйте накопление очереди и ошибки провайдера. Удаление профиля RevenueCat не отменяет платёжную подписку Google Play — об этом пользователь предупреждён до удаления.

RevenueCat хранит истину о покупке; повторные проверки не требуют локального копирования платёжных реквизитов. Состояние запрашивается при входе, после покупки/восстановления, возврате в приложение и не реже пяти минут при открытом платном доступе. При отмене сохраняется остаток оплаченного периода. Для legacy anonymous RevenueCat-покупателей нужна отдельная миграция: новая интеграция использует только собственный UUID аккаунта.
