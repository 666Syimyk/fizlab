# Аудит ФизЛаб 3D

Дата: 20 сентября 2026. Среда: Windows, Node.js 24.18.0, npm 11.16.0. Проверялось текущее рабочее дерево, включая существовавшие до аудита незакоммиченные изменения. Снимок исходного состояния и доказательства находятся в `audit.local/`; эта папка исключена из Git. Рабочая пользовательская база и сервер на порту 4174 не использовались для изменяющих тестов. Развёртывание, публикация, commit и push не выполнялись.

Завершение: вспомогательные серверы 4175/4177 и браузеры аудита остановлены, в отдельной базе `audit.local/runtime.sqlite` не осталось тестовых аккаунтов. Исходный процесс 4174 сохранён; серверные изменения в уже работающем процессе применяются после его обычного перезапуска. Готовый веб-клиент находится в `dist/client`, Worker — `dist/server/index.js`.

Эксплуатируемое чтение чужих данных без авторизации или SQL injection не подтверждены. Отсутствие такого воспроизведения не является доказательством отсутствия любых уязвимостей.

## 3. Исправленные CRITICAL-проблемы

`src/lib/progress.ts`, `progressSync.ts`, `AuthProvider.tsx`, `AccountPage.tsx` защищают данные от устаревших ответов и переключения пользователя. Повторный вход того же пользователя заново объединяет серверный прогресс; простой refresh токена не запускает лишнюю миграцию. Неудачный GET не разрешает отправить поверх неизвестной серверной копии пустое состояние. Снятые отметки не восстанавливаются старой копией устройства. При запрете/переполнении storage чтение использует актуальную копию в памяти.

В `server/worker.mjs` recovery code потребляется один раз, refresh одноразово обновляет существующую сессию, logout удаляет только предъявленный токен, а чувствительные записи повторно проверяют версию пароля внутри транзакции. Общая `src/lib/authMutations.ts` сериализует ручные изменения сессии; проверен настоящий SDK и две вкладки Chromium. Пароли и показанные резервные коды кабинета очищаются при смене аккаунта.

## 4. Исправленные HIGH-проблемы

Маршруты и симуляции имеют независимую обработку ошибок. Потеря WebGL-контекста и отсутствие WebGL2 показывают локальное сообщение. Сбой модуля симуляции не закрывает учебный текст. Прямые адреса темы/удаления работают в Cloudflare Assets без потери маршрута.

В линзе положение предмета в фокусе отражено как физическая бесконечность без `Infinity` в координатах. Нулевой заряд в поле Лоренца даёт прямую траекторию. Точный резонанс без затухания использует решение с растущей амплитудой, а не фиктивное конечное установившееся состояние. Газовые частицы создаются внутри стенок с учётом радиуса и пересоздаются при смене N/T/объёма. Давление использует реально прошедшее модельное время. Облако водорода рисует фактическое число принятых точек и обновляется при смене орбитали. Движение фотоэлектронов учитывает `dt`. Декоративный Sparkles на главной пересоздаётся при смене мобильного режима: установленная версия drei сохраняла часть буферов прежнего размера, что WebKit обнаружил как `glDrawArrays INVALID_OPERATION`.

## 5. UI/UX

Исправлены поиск по Arrow/Enter/Escape, состояние раскрытия и фокус меню, подписи паролей/переключателей, отключение повторной отправки, отображение ошибок входа/восстановления, подтверждение сохранения кода, загрузка аватара, пустой кабинет, переход к удалению, названия вкладок для assistive technologies. Удаление по-прежнему требует текущий пароль и явно объясняет последствия.

Кабинет различает «Синхронизация…», «Сохранено в аккаунте» и ошибку с повтором. При отсутствии постоянного локального хранилища сообщение честно указывает, что копия живёт только в текущей вкладке. Формулы/таблицы с намеренной горизонтальной прокруткой получили доступный фокус и название области.

## 6. Мобильная адаптация

Проверяемые ширины: **320, 360, 375, 390, 412, 430, 768, 820, 1024, 1280, 1366, 1440, 1920 px**. Дополнительный touch-сценарий использует 320×844, 390×844, 844×390, 1024×600 и максимально допустимые имена по 100 символов.

Корневой `overflow-x: clip` сохраняет закреплённую шапку. Параметры симуляции размещены в отдельной колонке/раскрываемом блоке и не закрывают canvas; на телефоне блок первоначально свёрнут. Устранён конфликт минимальной высоты сцены, добавлены переносы показателей/бейджей и профиля. Поля имеют 16px и на широком touch-экране; кнопки и вкладки на coarse pointer имеют минимум 44px высоты. Все ссылки не объявляются 44×44: проверяется также минимальная доступная область и расстояние между соседями.

Системная экранная клавиатура, safe areas конкретных телефонов, Android WebView и физический поворот устройства требуют отдельного прогона на устройствах.

## 7. Безопасность

Применены ownership predicate в SQL, параметризованные запросы и allowlist полей/таблиц, ограничения строк/массива/байтов, проверка JPEG, квоты auth/refresh/write с `Retry-After`, защита от подмены IP в локальном адаптере, атомарные credentials/session операции. JSON `null`, массивы/скаляры, специальные имена таблиц и неверные payload возвращают контролируемую ошибку.

API запрещает кэширование; HTML получает CSP/no-cache, hash assets — immutable; ответы включают nosniff, referrer policy и запрет framing, HTTPS — HSTS. CSP не разрешает произвольный inline JavaScript или `unsafe-eval`; `wasm-unsafe-eval` оставлен для физического движка. `style-src unsafe-inline` нужен используемым динамическим стилям. Подробный CSP и его ограничения перечислены в серверном отчёте.

Повторный статический проход охватил 652 файла, из них 538 текстовых, и 304 файла готового клиента: подтверждённых встроенных секретов нет; 15 совпадений password-pattern относятся к синтетическим тестам. Точные значения пяти непустых env-полей не найдены в исходниках или frontend dist; значения не публикуются. История Git и закодированные варианты секретов этой проверкой не покрыты. Android cloud backup и перенос данных явно исключают данные приложения. Матрица проверки ориентирована на [OWASP Top 10:2025](https://top10.owasp.org/2025/0x00_2025-Introduction/), но не является сертификацией или внешним penetration test.

`npm audit`: до исправления 11 предупреждений (5 high, 6 moderate), после чистой установки **0**. Это результат базы известных advisories, не количество доказанных эксплойтов приложения. Обновления выполнялись в пределах прямых manifest ranges; отдельный scoped override xcode→uuid11 проверен генерацией 1000 корректных уникальных project IDs. Для KaTeX проверена совместимость до выравнивания renderer/CSS. [Статический отчёт](audit.local/final-static-review.md), [npm audit JSON](audit.local/npm-audit-final.json).

## 8. Производительность

Устранены чтение чужих строк до фильтра, неограниченная выдача events, отсутствие нужного индекса, лишние миграции после token refresh, повторная инициализация газовых массивов при каждом render. Hero при reduced motion/вне видимости использует demand rendering. Сохранено существующее разделение lazy маршрутов, Three.js и Rapier; тяжёлые зависимости не переносятся в начальный React runtime.

Inter/Manrope поставляются локально: шесть WOFF2, 134 852 байта, `font-display: swap`, оригинальные лицензии и SHA-256. Убрана зависимость загрузки текста от Google Fonts и inline onload. Проверяются размеры готовых chunks/изображений, а не обещаются production Core Web Vitals на основании локального компьютера.

Обнаружено расхождение KaTeX: wrapper использовал 0.16.47, а CSS и validator — 0.17.0. Перед выравниванием проверены все 12 932 выражения в обоих режимах напрямую и настоящим React wrapper: ноль различий HTML, 60/60 файлов шрифтов идентичны, CSS отличается только строкой версии. Scoped override и regression закрепляют одну версию. Это исправление совместимости и качества проверки; существенная экономия browser bundle не заявляется. [Полное сравнение](audit.local/katex-compat-review.md).
